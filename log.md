This file lives at the root of the project root, alongside (not inside) `procedural-memory/` and `semantic-memory/`, since it logs changes to both.

- **Procedural Memory (Skills) Updates**: changes (addition, removal, update) made to procedural memory; each new record is appended to the end of the table.
- **Semantic Memory (Knowledge Pages) Updates**: changes (addition, removal, update) made to semantic memory; each new record is appended to the end of the table.

## Lint Runs

Record of every `memory-lint` pass, one row per lint run — plus exactly one extra row at the bottom that is always **open** (pending), representing the batch of items accumulated since the last completed run.

**How the open row works:**
- Its `Lint Run Timestamp` is **empty**. An empty timestamp is what marks a row as open/pending rather than a completed run.
- Every time a new skill or knowledge page is added or updated (via `memory-ingest`), that item's name is appended to the open row's `New Items Reviewed` cell — live, at the time of the addition, not computed later by scanning timestamps.
- `memory-lint`'s step 0 only has to read this one cell and count the names in it — no timestamp math. If the count meets the threshold, it lints; if not, it stops.
- When `memory-lint` actually runs (past step 0), it fills in the open row's `Lint Run Timestamp` with the current time and fills in `Findings`/`Actions Taken` — this **closes** that row into a completed record. It then appends a fresh row below with an empty `Lint Run Timestamp` and an empty `New Items Reviewed`, which becomes the new open row.
- At any given time there is exactly one open row (the last one), and it's always at the bottom of the table.

Column definitions:
- **Lint Run Timestamp** — when that lint pass actually ran (steps 1 onward, not step 0's check). Empty = this row is still open/pending, not yet run.
- **New Items Reviewed** — item names, comma-separated, in the order they were added. For a closed row, this is the exact set that pass covered. For the open row, this is the current backlog.
- **Findings** — specific issues identified, naming the actual items involved. Empty until the row is closed.
- **Actions Taken** — one-to-one with Findings: `merged X into Y`, `fixed broken link to Z in W`, `removed X (superseded by Y), updated references in A/B/C`. Empty until the row is closed.
